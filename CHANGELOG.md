# Changelog

Notable changes and release rationale for Repertoire, newest first.

## v2.5.1 — 2026-09-04

Fixes an issue where the cross-model Codex fallback CLI (`codex exec`) could hang indefinitely in non-interactive environments when stdin is connected to an unclosed pipe ([openai/codex#20919](https://github.com/openai/codex/issues/20919)). Standardizes the fallback pattern across all skills: prompt and verdict files are used for I/O, stdin is closed (`< /dev/null`), a strict timeout is enforced, and execution runs inside background subagents to avoid blocking the orchestrator. Tuner's fallback and shared contract specifications in `shared/invariants.md` have been updated to match.

## v2.5.0 — 2026-08-03

Adds opt-in support for GitHub stacked pull requests (`gh-stack`) for multi-plan sets generated by Score. Plans can declare a `stacked chain` execution shape in `00-overview.md`, allowing dependent plans to branch from their parent plan and automatically link via `gh stack link`. This isolates diffs for each review and QC stage while keeping merges strictly user-controlled. Gracefully falls back to standard pull requests targeting parent branches if `gh-stack` is unavailable.

## v2.4.1 — 2026-08-01

- **Legato Skill**: Adds `legato`, a dedicated skill for UI motion and animation polish based on Emil Kowalski's animation standards (bundled under MIT license in `references/`). Uses scoped audits, an interactive direction gate, an implementer subagent, and dedicated motion review to refine interfaces, saving persistent project animation guidelines to `docs/repertoire/animation.md`.
- **Jam Backlog Persistence**: Adds persistent backlog tracking in target projects (`docs/repertoire/jam-backlog.md`). Candidates not selected and jobs dropped during unattended sessions are preserved with priority ratings and re-evaluated in subsequent runs instead of being lost.

## v2.3.0 — 2026-07-31

Introduces `jam`, an autonomous development skill for unattended repository improvements. Three parallel Opus scouts analyze the codebase across features, bug fixes, and UI/UX polish; a selector assembles a curated 3–5 task docket; and subagents implement, review, and test changes sequentially. Failing tasks are cleanly reverted rather than blocking progress, and branch-level verification pairs Opus with the session model to provide robust review coverage without external dependencies.

## v2.2.0 — 2026-07-25

Introduces `presto`, a fast-track skill designed for small, well-scoped changes completed in a single session without requiring upfront specs or multi-stage plans. A size gate allows the controller to implement minor changes directly (≤150 lines, ≤3 files) to reduce latency, while delegating larger tasks to an implementer subagent. Includes independent Opus review and build/test QC, with automatic escalation to Libretto, Score, or Maestro if scope expands or tests fail repeatedly.

## v2.1.0 — 2026-07-11

Expands `score` to support multi-plan sets for large initiatives. When work spans multiple plans, Score generates a coordinating `00-overview.md` with cross-plan interface contracts, dispatches parallel subagents to author individual plan files, and verifies overall coherence through a cross-plan review panel.

## v2.0.0 — 2026-07-10

Transitions all skills from manual-only to auto-invocable, with refined descriptions and `when_to_use` criteria. Introduces upfront confirmation gates for token-intensive autonomous pipelines (Maestro, Coda, Tuner) and standardized trigger evaluation suites in `evals/evals.json`. Consolidates shared Codex reviewer contracts under `shared/` and optimizes test execution scopes.

## v1.7.0 — 2026-07-01

Implements a flexible two-tier model policy: build roles (implementers, fixers, QC gates) inherit the session model (`best` / Opus / Fable), while review roles (reviewers, verifiers, panels) remain pinned to Opus for consistent adversarial rigor.

## v1.6.2 — 2026-06-16

Operational adjustment pinning all subagents to Opus at maximum reasoning effort following temporary export-control restrictions on Claude Fable 5.

## v1.6.1 — 2026-06-09

Model tuning release aligning Claude subagent dispatches with high reasoning effort and consolidating shared cross-model review contracts.

## v1.6.0 — 2026-06-07

Introduces `encore`, an enhancement skill that audits completed codebases for performance, security, reliability, and developer experience opportunities. Identified improvements are verified against the codebase and presented for user selection before implementation.

## v1.5.0 — 2026-06-07

Introduces `eureka` for early-stage idea exploration, structured brainstorming, and candidate vetting. Adds multilingual documentation (Simplified Chinese, Traditional Chinese, and Japanese).

## v1.4.0 — 2026-06-06

Introduces `tuner`, a root-cause debugging skill that pairs rival Codex and Opus investigators to cross-examine fault hypotheses, applying minimal, test-driven repairs validated by red-to-green verification.

## v1.3.0 — 2026-06-06

Introduces `coda`, a skill for processing pull request feedback and CI failures. Verifies review comments against the codebase, implements necessary fixes, validates changes with QC and cross-model reviews, and prepares draft replies for user approval.

## v1.2.0 — 2026-06-06

Introduces `score`, transforming approved design specifications into detailed, decision-complete implementation plans with precise file paths, interfaces, and test criteria, validated by an adversarial review panel.

## v1.1.0 — 2026-06-03

Introduces `libretto`, a guided design dialogue skill that refines rough concepts into build-ready technical specifications, hardened by an adversarial subagent review panel.

## v1.0.2 — 2026-06-03

Fixes catalog metadata display in the plugin UI and aligns version synchronization between `plugin.json` and `marketplace.json`.

## v1.0.1 — 2026-06-03

Initial open-source release setup, including Apache-2.0 licensing and repository documentation.

## v1.0.0 — 2026-06-03

Initial release featuring `maestro`, an orchestrator that conducts implementation plans using specialized subagents for task execution, adversarial review, and quality-control verification.
