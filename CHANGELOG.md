# Changelog

One paragraph per release, newest first. Each entry explains why the release happened, not what every commit touched — the git log holds the diff-level detail.

## v2.4.1 — 2026-08-01

Jam stops forgetting between sessions. Until now the road not taken — the selector's notable rejects and the jobs dropped or amputated mid-run — lived only in one session's report, so the next Jam re-scouted the same repo blind and could rediscover, or miss, the same candidates. A shipped run now ends with a new Phase 5 that writes `docs/repertoire/jam-backlog.md` into the *target* project: rejects scored 1-5 by the selector plus dropped jobs entering at P4 with their drop reason on the line, sorted by lens, capped at twelve entries, superseded in place — Legato's standing-record pattern, and the conductor's own pen under an explicit bookkeeping carve-out because the file is composed from reports, never from code. The pool closes the loop on the way back in: the next session's scouts each receive their lens's entries and must re-verify every one against current source before it may compete again — carried entries count toward the six-candidate cap and win on merit, never seniority — while stale entries come back on a `Stale backlog` line and are pruned at the next write. Routing surface unchanged; no eval re-run needed.

Legato gives the line an opinion about motion. "The dropdown animation feels sluggish" had no room of its own: too small for spec-to-plan-to-build, not a bug (Tuner), not a general enhancement pass (Encore), and Presto — the right size — has no idea what good motion is. Legato does, because it borrows its taste on the record: the operational files of Emil Kowalski's MIT-licensed skills repository — the exact-values standards, the eight-category audit playbook, the naming vocabulary — are copied verbatim into `skills/legato/references/` with provenance headers and the license reproduced, the philosophy distilled into the prompts, and the skill's load-bearing rule is that any value appearing in those files is copied, never approximated ([ADR 0007](docs/adr/0007-legato-borrows-its-taste-and-keeps-a-record.md)). The pipeline is Presto-shaped — one pinned-Opus scout audits the named surface (with an optional live look through a browser when the app is already running — never started, only used), the user locks direction at one AskUserQuestion gate where a concrete goal is grilled against the standards and an undecided user gets at most three directions, then one implementer, one pinned-Opus reviewer holding the diff to the ten non-negotiable standards, and a build-and-test QC gate — but the conductor never plays, because the approved motion spec *is* the implementer's context and ADR 0005's latency argument dissolves when the handoff costs nothing to assemble. What outlives the run is new for the line: Phase 7 writes standing guidance into the *target* project at `docs/repertoire/animation.md` — motion language, per-surface decisions, rejected directions — superseded in place so it never becomes a changelog, honored by later runs, and pointed to from the project's CLAUDE.md or AGENTS.md only behind a one-time consent question. The third sanctioned no-Codex variance lands with the skill, for Presto's reason, and adjacency went reciprocal on day one: presto, encore, jam, and tuner each gained a legato clause or boundary eval, eureka a boundary eval. The pre-release adversarial review (three lenses: self-consistency, cross-file drift, routing surface) returned thirty-seven findings — among them a below-the-floor carve-out that could have edited the user's tree on main before any consent, a resume contract that lost the locked motion spec the moment the conversation died, all four READMEs' Codex-prerequisite bullet stale for the third release running, a routing surface that never claimed *adding* motion while its own evals did, and an ADR whose attribution list disagreed with the bundled LICENSE — all fixed before this bump.

## v2.3.0 — 2026-07-31

Jam hands the line its first set of car keys. Every skill through v2.2.0 assumed a user somewhere load-bearing — a dialogue, an approval gate, a named target, a written plan — which left one standing request with no room of its own: "make this project better, you pick what to do." Jam owns that mandate as a fully unattended session, and the release's real content is how it makes autonomy safe instead of reckless: the user's judgment is replaced by structure, not skipped. Three read-only Opus scouts study the repo in parallel from its end users' seat — non-breaking features, quick fixes users are silently paying for, UI/UX polish — with every candidate anchored at `file:line` or it dies; an Opus selector, not the scouts' enthusiasm and not the conductor, composes a 3-5 job docket under a hard non-breaking rule and an L-size ban; and the docket is *announced, not approved* — the run stops for exactly three things (the auto-invoke cost gate, Phase-0 blockers only the user can resolve, and QC's two-strike escalation). The conductor never plays — ADR 0005's latency argument does not apply when no user scoped anything — but review bends where it can afford to: per-job review is at the conductor's discretion behind the selector's `required`/`optional` flags, while the finale never thins — two whole-branch reviewers plus an evidence-based QC that builds, tests, and can amputate an unshippable job by clean revert, because an unattended run prefers shrinking the docket to stalling on it. The second sanctioned no-Codex variance lands with the skill, for a new reason: a cross-model call that hangs has no user at the wheel to notice, so Jam buys its reviewer diversity cross-tier instead — a pinned-Opus finale reviewer beside one unpinned on the session model ([ADR 0006](docs/adr/0006-jam-runs-unattended.md), `shared/invariants.md`). Adjacency went reciprocal in the same release: eureka, encore, and presto each gained a jam clause and a boundary eval, maestro a boundary eval, and jam's own evals pin the hard edges — including the colloquial "let's jam on some ideas", which contains the skill's name and belongs to eureka. The pre-release adversarial review (three lenses: self-consistency, cross-file drift, routing surface) returned twenty-one findings — among them all four READMEs' Presto rows still claiming the "only skill without Codex" fact this release was amending, a drop rule and a QC gate holding contradictory standards for the same partial commits, a resume contract whose docket never survived an interrupt, and a seat count that contradicted its own nominal path — all fixed before this bump.

## v2.2.0 — 2026-07-25

Presto opens a door the line never had. Under the production pipeline a user who wanted a `--json` flag added to one command had two options — write a spec, write a plan, and conduct a ten-seat Maestro run over thirty lines of change, or get nothing, since Maestro's own guidance says a small one-off task needs no pipeline and then names no door. Presto is that door: 1-2 read-only Opus scouts map the landing zone and weigh approaches, the user picks at a single AskUserQuestion gate before anything is written, and then a **size gate** decides who builds it. That gate is the release's real content, because it breaks the invariant every other *building* skill holds — the conductor never plays. Inside it (recon left no open questions, roughly ≤3 files and ≤150 lines, one module, no new subsystem, dependency, schema, or public interface) the controller implements the change itself, on the reasoning that dispatching a subagent to reconstruct context the controller already holds is pure latency; outside it, one implementer subagent takes the work, and growing past the gate mid-build is a documented stop-and-hand-off rather than a licence to keep going. What the compression never touches is scrutiny: the reviewer is always a fresh Opus subagent, most of all when the controller was the author, and the run still closes on a build-and-test QC gate. Repair gets one narrow extension of the same carve-out — the controller may fix `minor` findings in place whoever wrote them — routed on the severity the reviewer assigned rather than on the controller's read of its own convenience. Speed here comes from fewer seats, not shallower thinking: every seat still runs at xhigh, there are just three on the floor and six on the nominal path, and what the budget forbids is growing the ensemble *by design* — a third scout, a second review round, a panel. Two doors lead out, and taking either is a successful run: oversized work leaves at the approval gate for Libretto or Score, and a change that fails QC twice goes to Maestro (the strike budget is two rather than Maestro's three, because two failed rounds in a fast lane is evidence the work was mis-sized). Two deliberate consequences are recorded in `shared/invariants.md` and [ADR 0005](docs/adr/0005-the-controller-plays-in-presto.md): Presto pins its recon scouts to Opus, since their approach recommendation is the only investigation the run gets, and it is the one skill in the line with no cross-model Codex seat — that pass earns its wall-clock over a whole branch, not over one scoped change. Adjacency is made reciprocal in the same release rather than left one-sided: Maestro's `when_to_use` stops saying a small one-off task "needs no pipeline at all" and names Presto's door instead, and maestro, tuner, and encore each commit boundary cases pointing at it. A pre-release adversarial review over the whole branch returned eleven findings — among them a seat-ceiling that contradicted its own retry budget, a repair clause worded broadly enough to license the controller editing an implementer's code, a Phase 0 that cut the branch before the gate meant to confirm it, and an unrecoverable resume — all fixed before the version bump.

## v2.1.0 — 2026-07-11

Score learns to think in suites. Until now a goal that outgrew one plan hit the scope check's blunt answer — plan one subsystem, come back for the rest — which serialized what was really one coordinated piece of work. The scope check becomes a plan-count decision: when one goal spans several plans' worth of work, Score proposes a plan set at the existing structure checkpoint (no new gate), then authors `00-overview.md` itself — the plan inventory, execution order, and the cross-plan interface contracts that no single plan can carry — and dispatches one unpinned plan-writer subagent per plan file, in parallel, into a dated directory. Writers return interface manifests (defines / consumes / missing contracts) so the controller reconciles seam drift without reading every plan, keeping the author context lean for exactly the work that stays its own: the partition, the overview, and the revision after review. The panel reads the whole set and gains a mandatory cross-plan coherence lens; a single plan is untouched — same lone file, no overview, no writers. The release passed an adversarial consistency review across all seven skill files before shipping, and the routing surface plus trigger evals grew two multi-plan cases in the same edit.

## v2.0.0 — 2026-07-10

The flip. Every skill drops MANUAL-ONLY and becomes auto-invocable: the long negative-trigger descriptions are rewritten as a positive `description` plus `when_to_use`, sized against the 1,536-character listing cap — and the audit that preceded the rewrite discovered the cap had been silently truncating the two longest 1.x descriptions all along, so part of the negative guidance the old policy relied on was never reaching the router in the first place. Adjacency clauses that name the neighboring skill replace negation, and the doctrine behind the rewrite is committed at `docs/authoring/skill-descriptions.md`. Because a skill that can now fire on its own must not spend money on its own, the three pipelines that dispatch subagents before any user gate — maestro, coda, tuner — gain an in-skill cost gate: one `AskUserQuestion` before the fleet launches. Routing quality becomes a regression surface rather than a one-off tuning exercise: every skill commits trigger evals at `skills/<name>/evals/evals.json`, with auto-invoke polarity, cross-skill confusion pairs, and homonym cases. The release also pays down run cost ahead of the wider audience auto-invoke will bring: implementer and fixer test runs are scoped to the touched areas (the full suite runs once, at the QC gate), QC gains a retry-round mode that close-reads only the new fixes, Maestro skips its Phase-1 fixer entirely on a clean reviewer PASS, and four seats are retuned down a tier — the triage scout and feedback clerk to medium, Tuner's verifier and Eureka's ideators from xhigh to high. Finally, the seven dot pipeline graphs are replaced by phase-numbered at-a-glance checklists (same topology, roughly a fifth of the tokens, no more graph/prose drift), and the per-skill codex-reviewer prompts are consolidated into one `shared/` contract instead of seven drifting copies.

## v1.7.0 — 2026-07-01

Fable 5 came back, and instead of hardcoding it again the plugin learned from the suspension: a two-tier model policy. Build seats (implementers, fixers, QC and final gates, Tuner's scout, Eureka's ideators, Coda's feedback clerk) dispatch unpinned and inherit the session model, so `/model best` routes Fable-where-available, else Opus, with no model name baked in to break on the next suspension. Review seats (reviewers, evidence verifiers, Tuner's investigator and fix reviewer, the vetting/spec/plan panels, Encore's hunters) stay pinned to Opus for a stable adversarial baseline. Never Sonnet; effort stays xhigh.

## v1.6.2 — 2026-06-16

An externally forced release: Anthropic suspended Claude Fable 5 access on 2026-06-12 under a US export-control directive, four days after v1.6.1 had put Fable on every seat. Every dispatch moved to Opus at xhigh — the strongest model still available, at maximum reasoning depth — with a temporary notice to switch back when Fable returned. The "only xhigh seat" framing for Tuner's investigator was dropped, since every seat was now xhigh.

## v1.6.1 — 2026-06-09

A pure model retune, two days after the pipeline was declared complete: every Claude subagent seat moved to Fable 5 at high effort, with xhigh reserved for Tuner's investigator to keep parity in the cross-model root-cause duel against Codex. The same window committed the Eureka cost-and-reuse shortlist that would seed the 2.0 line — consolidating the Codex contract into shared parts was already the champion idea.

## v1.6.0 — 2026-06-07

Encore closed the 1.x line — the curtain call. A post-performance enhancement pass over a finished codebase: a scout profiles the target, an adaptive lens roster is agreed with the user, parallel Opus hunters find opportunities, a verifier kills anything the codebase refutes, and only what the user picks at the set-list gate gets built. With it the music line stood complete: Eureka → Libretto → Score → Maestro → Coda → Encore, plus Tuner off to the side for debugging.

## v1.5.0 — 2026-06-07

Eureka gave the pipeline its opening movement: everything downstream assumed the user already held an idea worth speccing, and discovery was the missing phase. It is deliberately conversation-heavy — seed sketches, a running idea board, on-demand ideator bursts — ending in a vetting funnel where every kill verdict needs user confirmation, and its terminal artifact is a ranked shortlist handed to Libretto, never a spec. The docs also went multilingual in this window (zh-CN, zh-TW, ja READMEs with a language switcher).

## v1.4.0 — 2026-06-06

Tuner added the first skill outside the production line: a cross-model debugging conductor that races a Codex investigator against a triage-primed Opus investigator, cross-examines their rival root-cause hypotheses as the confidence gate, and lands the fix behind a failing-test-first fixer and a red→green verifier. The release also refactored Coda's ending — a staged final verdict, with the broad re-review folded into QC — shortened the plugin description as the catalog entry grew unwieldy, and documented the honest operating cost: a Codex plugin and Max/API billing are recommended for these token-heavy skills.

## v1.3.0 — 2026-06-06

Coda extended the pipeline past the merge gate into the PR conversation. Its stance is that review feedback is a claim, not an order: every formal review, inline thread, and failing check is verified against codebase reality by a read-only Opus verifier before anything is fixed — no blind implementation, no performative agreement — and pushing and posting the drafted replies sit behind one user approval. The release also closed Score's own review-panel findings, eating the plugin's dog food.

## v1.2.0 — 2026-06-06

Score filled the gap between Libretto's spec and Maestro's build: an approved spec becomes a decision-complete implementation plan — movements of Maestro-ready task groups with exact paths, interfaces, and test expectations, but no function bodies — hardened by the same adversarial panel pattern (2-3 Opus lenses plus a cross-model Codex reviewer) behind a user-approval gate. Adapted from superpowers writing-plans; Libretto's handoff was rewired to point at it.

## v1.1.0 — 2026-06-03

Libretto made Repertoire a pipeline rather than a single skill: a guided design dialogue that turns a rough idea into a build-ready spec, hardened by an adversarial review panel before a final approval gate. Adapted and compacted from superpowers brainstorming, it set the shape everything after it followed — the controller does the thinking, subagents do the reading and the skepticism, and the terminal artifact is a document, never code.

## v1.0.2 — 2026-06-03

Marketplace-plumbing corrections from watching the `/plugin` UI: the catalog entry wasn't surfacing the plugin version, so it was added there and the entry enriched (category, tags, homepage), descriptions were compacted, and the lesson was written down as the two-place version rule — `plugin.json` drives resolution, the `marketplace.json` entry drives what the UI shows, and the two must be bumped together or they drift.

## v1.0.1 — 2026-06-03

Made the repo publishable as an open project: an Apache-2.0 LICENSE, a maintainer email in the manifest, and a CLAUDE.md guide so future sessions understand the one-plugin topology before touching it.

## v1.0.0 — 2026-06-03

The founding release: the Maestro skill — a conductor that executes an implementation plan through fresh implementers, an adversarial review panel, and an evidence-based QC merge gate, never reading code itself — packaged as the Repertoire plugin shipping through its own one-entry marketplace. The repo root is simultaneously the marketplace root, the plugin root, and the source tree, which is the topology decision everything since has leaned on: adding a skill never touches the marketplace.
